## 已修改

1. **先记录再解析**：每次调用保存请求上下文、原始 content、服务返回的 reasoning_content、finish_reason、usage 与最终状态。记录放在 `model_responses/<row_id>/<attempt>.json`；解析失败也保留。仅保存在本地输出目录，已配置 key 脱敏，不写请求头或 HTTP 异常正文。
2. **契约修复**：兼容单个完整 JSON 外的说明/代码围栏；拒绝重复键、多对象、截断、非有限数值。`alternatives` 为说明字段，字符串转列表、null 转空列表、对象保留为 JSON 文本；不支持的可选项省略并留审计记录。评分字段和证据引用仍严格校验，不从说明字段猜测根因。
3. **有界纠错**：首轮格式或字段错误可同模型纠错一次，与补查/复核共用最多两轮逻辑调用；第二轮失败不能再开第三轮。每次实际请求都计费并检查总预算。无法保证旧 A/B 的真实坏输出都可恢复，因为其正文已缺失。
4. **服务熔断**：仅连接/超时、408/429/5xx 或缺少 choices 的服务响应计入服务故障。连续两次后冷却 60 秒再探测；有效服务响应清零。格式错误单独记录，禁止因为坏 JSON 把后续案例的模型永久跳过。
5. **便宜模型优先**：完整遥测的单故障先快速模型，多故障/证据缺失先强模型。快速模型要求补查或返回低置信度时第二轮可升级；格式纠错不自动升级。若复核失败，保留已通过校验的低置信度草稿。新策略在旧初筛证据上回放为 fast 6 / strong 1；这是首轮选择回放，不是在线节省成本的证明。
6. **诊断归因**：traces 增加路由原因、输出校验/归一化、采用哪轮答案、与启发式是否不同。工具增加查询阶段、预算和实际耗时，超时仍作为缺失证据，不自动无限重试或提高超时上限。

## 额外发现：证据排序需要单独实验

row 0 的 `container_memory_failures.hierarchy.pgfault` 基线、P05、P95 全为 0，窗口最大值 51694.5。
旧分数使用 `max(abs(baseline)*0.05, P95-P05, 0.000001)` 作分母，因此得到 51,694,500,000。
同组件另一个 pgfault KPI 也占据前排。其他案例也出现零基线导致巨大分数。

这说明跨 KPI 排序容易被单位、零基线和重复信号主导。pgfault 本身不能证明内存负载注入，模型即便复核也可能缺少区分原因的证据。
这是一个可检验的候选解释，**不是**已经证实的全部无增益原因。本轮保持检索数值和回退算法不变，避免把可靠性修复与检索算法调整混成一个实验。
