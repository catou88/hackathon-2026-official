## 提交前优先处理

1. **正式命令默认不运行路由模型。** `mini_rca/cli.py:37` 默认 `offline`，官方仅传 dataset/queries/out，结果是无模型回退。实际用这三个参数跑两例，均为 `offline-fallback`，费用 $0，整轮 12.172 秒。CLI 能运行不等于所申报的路由 Agent 被运行。正式提交入口应默认采用自研路由模式，同时保留显式离线开发模式。
2. **缺少本 Agent 的可构建提交包。** `agentstest` 有 run.py 和 eval/，没有 Dockerfile、根目录 REPORT.md；eval/ 目前仅含评分器及许可，实验结果在被 `.gitignore` 排除的 out/。其他目录的 Dockerfile 打包的是旧 starter，未连接 mini_rca。不能以其存在来证明本 Agent 可部署。按官方补充说明，子目录项目可接受唯一 Dockerfile，但多个 Dockerfile 会产生构建歧义。
3. **官方校验器实际失败。** `Track1/scripts/validate_submission.py` 总会附加 `--agent`；本入口不支持，退出码 2，错误为 `unrecognized arguments: --agent agents.heuristic`。更换 VAL_AGENT 只改参数值，不能解决缺失参数。需提供兼容入口/适配，不能把通过自定义测试等同于官方 validate 已通过。`Controller.solve(Case)` 也不是 starter 的模块级 `solve(instruction,dataset_dir,ctx)` 接口；这是 starter 接入差异，不能误说三个正式 CLI 参数缺失。
4. **提交材料未完成。** README 和主要设计说明为中文，缺少英文提交 REPORT 与约四分钟英文展示。已有通用 AI 生成说明，但未明确列出编码助手名称及团队/AI 的具体分工。未见本 Agent 的公开仓库链接、推送状态或提交回执；这些属于未确认，不能据本地文件断言用户未在外部提交。
